# JQL

EJDB query language (JQL) is designed for querying and updating sets of JSON documents.
Its syntax is inspired by ideas behind XPath and Unix shell pipes: a query is a chain of
`|`-separated sections that filter documents, modify them, project a subset of fields, and
finally tune the result set.

## JQL grammar

The JQL parser is generated by
[peg/leg — recursive-descent parser generators for C](http://piumarta.com/software/peg/).
The formal parser grammar is [jqp.leg](https://github.com/Softmotions/ejdb/blob/master/src/jql/jqp.leg).
The overview below is a readable equivalent of that grammar; `jqp.leg` is the source of
truth whenever they disagree.

## Grammar overview

Notation used below is based on SQL syntax description:

Rule | Description
--- | ---
`' '` | String in single quotes denotes a keyword or a punctuation character of the query.
<code>{ a &#124; b }</code> | Curly brackets enclose two or more required alternative choices, separated by vertical bars.
<code>[ ]</code> | Square brackets indicate an optional element or clause.
<code>&#124;</code> | Vertical bars separate two or more alternative syntax elements.
`...` | Ellipses indicate that the preceding element can be repeated.
<code>( )</code> | Parentheses are grouping symbols.
Unquoted word in lower case | Denotes a semantic part of the query. For example: `placeholder_name` — name of a placeholder.

```
QUERY = ( FILTEREXPR | FILTER_PK )
        [ '|' ( APPLY | UPSERT | 'del' ) ]
        [ '|' PROJECTIONS ]
        [ '|' OPTS ];

FILTEREXPR = FILTERFACTOR { FILTERJOIN FILTERFACTOR };

  FILTERFACTOR = FILTER | '(' FILTEREXPR ')';

  FILTERJOIN = ( 'and' | 'or' ) [ 'not' ];

  FILTER = [ '@' collection_name ] NODE { NODE };

  FILTER_PK = [ '@' collection_name ] '/' '=' ( PLACEHOLDER | NUMBER | NUMBER_ARRAY );

  NODE = '/' ( STR | STRP | NEXPR );

  NEXPR = '[' NEXPAIR { NEXJOIN NEXPAIR } ']';

  NEXPAIR = NEXLEFT NEXOP NEXRIGHT;

  NEXLEFT = '**' | '*' | STR | STRP | NEXPRLEFT;

  NEXPRLEFT = '[' '*' NEXOP NEXRIGHT ']';

  NEXRIGHT = PLACEHOLDER | JSON_VALUE | STRP;

  NEXJOIN = ( 'and' | 'or' ) [ 'not' ];

  NEXOP = [ 'not' ] ( 'in' | 'ni' | 're' )
        | '>=' | 'gte' | '<=' | 'lte' | '>' | 'gt' | '<' | 'lt'
        | [ '!' ] ( '=' | 'eq' | '~' );

APPLY = 'apply' ( PLACEHOLDER | JSON_OBJECT | JSON_ARRAY );

UPSERT = 'upsert' ( PLACEHOLDER | JSON_OBJECT | JSON_ARRAY );

PROJECTIONS = PROJNODES { ( '+' | '-' ) PROJNODES };

  PROJNODES = 'all' | PROJNODE { PROJNODE };

  PROJNODE = '/' ( '{' PROJPROP { ',' PROJPROP } '}' | PROJPROP );

  PROJPROP = STR | STRP | PLACEHOLDER | join_prop;

OPTS = OPT { OPT };

  OPT = 'skip' ( NUMBER | PLACEHOLDER )
      | 'limit' ( NUMBER | PLACEHOLDER )
      | 'count'
      | 'noidx'
      | 'inverse'
      | ( 'asc' | 'desc' ) ( ORDERNODES | PLACEHOLDER );

  ORDERNODES = ORDERNODE { ORDERNODE };

  ORDERNODE = '/' PROJPROP;

STR = quoted string;
STRP = unquoted string;
PLACEHOLDER = ':' ( placeholder_name | '?' );
join_prop = field_name '<' collection_name;
```

* `JSON_VALUE` is any valid JSON value: object, array, string, number, boolean, or `null`.
* `STR` is a double-quoted string with JSON escapes, e.g. `"John Doe"`, `"a.b"`.
* `STRP` is an unquoted string. It cannot contain spaces, tabs, newlines,
  or any of `/ " [ ] = > < ! ( )`. Use a quoted string for anything else.
* `join_prop` is recognized at runtime: a projection property containing `<`
  is treated as a join (see [JQL collection joins](#jql-collection-joins)).
* `json_path` used below is a simplified JSON pointer, e.g. `/foo/bar` or `/"bar with spaces"`.

## Query structure

A query consists of up to four `|`-separated sections, always in this order:

1. **Filters** (required) — select documents.
2. **Modification** (`apply`, `upsert`, or `del`) — change matched documents.
3. **Projections** — return only a subset of each document.
4. **Options** (`skip`, `limit`, `count`, `noidx`, `inverse`, `asc`/`desc`) — affect
   the result set. All options belong to the same section: `| asc /age limit 2`,
   not `| asc /age | limit 2`.

Any of the last three sections can be omitted.

## JQL quick introduction

Let's play with some basic data and queries.
For simplicity we use the EJDB HTTP/WebSocket server (`jbs`), which also provides an
interactive `wscat` client. The same queries work through the `C` API
(`ejdb2.h`, `jql.h`) and the language bindings.

NOTE: See the [JQL tests](https://github.com/Softmotions/ejdb/blob/master/src/jql/tests/jql_test1.c)
for more examples.

### Sample data

```json
{
  "firstName": "John",
  "lastName": "Doe",
  "age": 28,
  "pets": [
    {"name": "Rexy rex", "kind": "dog", "likes": ["bones", "jumping", "toys"]},
    {"name": "Grenny", "kind": "parrot", "likes": ["green color", "night", "toys"]}
  ]
}
```

Start the server:

```sh
./jbs -a 'myaccess01'
8 Mar 16:15:58.601 INFO: HTTP/WS endpoint at localhost:9191
```

Documents can be added over HTTP:

```sh
# Document 1
curl -d '{"firstName":"John","lastName":"Doe","age":28,"pets":[{"name":"Rexy rex","kind":"dog","likes":["bones","jumping","toys"]},{"name":"Grenny","kind":"parrot","likes":["green color","night","toys"]}]}' \
     -H'X-Access-Token:myaccess01' -X POST http://localhost:9191/family

# Document 2
curl -d '{"firstName":"Jack","lastName":"Parker","age":35,"pets":[{"name":"Sonic","kind":"mouse","likes":[]}]}' \
     -H'X-Access-Token:myaccess01' -X POST http://localhost:9191/family

# Document 3
curl -d '{"firstName":"John","lastName":"Ryan","age":39,"tags":["a","bestseller"],"meta":{"x":{"y":7}},"active":true,"score":1.5,"nil":null}' \
     -H'X-Access-Token:myaccess01' -X POST http://localhost:9191/family
```

The interactive [wscat](https://www.npmjs.com/package/@softmotions/wscat) client is
handy for experimenting:

```sh
wscat -H 'X-Access-Token:myaccess01' -c http://localhost:9191
connected (press CTRL+C to quit)
> k @family/*
< k     3       {"firstName":"John","lastName":"Ryan","age":39,"tags":["a","bestseller"],"meta":{"x":{"y":7}},"active":true,"score":1.5,"nil":null}
< k     2       {"firstName":"Jack","lastName":"Parker","age":35,"pets":[{"name":"Sonic","kind":"mouse","likes":[]}]}
< k     1       {"firstName":"John","lastName":"Doe","age":28,"pets":[{"name":"Rexy rex","kind":"dog","likes":["bones","jumping","toys"]},{"name":"Grenny","kind":"parrot","likes":["green color","night","toys"]}]}
```

The `k` prefix is an arbitrary key chosen by the client. It is returned with the response
and lets the client match a response to its request.
[More info](https://github.com/Softmotions/ejdb/blob/master/src/jbr/README.md)

A query can also be executed over HTTP:

```sh
curl --data-raw '@family/[firstName = John]' -H'X-Access-Token:myaccess01' -X POST http://localhost:9191
1	{"firstName":"John","lastName":"Doe","age":28,"pets":[...]}
```

The collection can be supplied by the command (`k query <collection> <query>`) or
in the query itself (`@collection/...`). **Most examples below are shown as typed in
`wscat` and include the `k` prefix**; blocks without a `>` prompt show the plain JQL
text. The `@family` anchor is required when a query is executed over HTTP or through
the `ejdb2` API without an explicit collection name.

## JQL filters

### Collection anchor

`@collection/...` selects the collection. A query is always executed against one
collection — the first anchor in the query is used.

### Getting all documents

```sh
> k @family/*
```

`/*` and `/**` as the only path node also match every document.

### Existence of a JSON path

A path without an expression matches documents where the path exists:

```sh
> k @family/tags
< k     3       {"firstName":"John","lastName":"Ryan","age":39,"tags":["a","bestseller"],...}

> k @family/pets
< k     2       {"firstName":"Jack","lastName":"Parker","age":35,"pets":[...]}
< k     1       {"firstName":"John","lastName":"Doe","age":28,"pets":[...]}

> k @family/nil
< k     3       {"firstName":"John","lastName":"Ryan","age":39,...,"nil":null}
```

### Path nodes: `*`, `**`, and array positions

| Node | Matches |
--- | ---
`/field` | Object key `field` (exact name). Array element position when the parent is an array.
`/"quoted name"` | Object key with spaces or special characters.
`/*` | Any key name at exactly one nesting level (and any array element).
`/**` | Any key name at any nesting level, including zero levels.
`/0`, `/1`, ... | Array element at the given zero-based position.

```sh
# Element at index 1 of every `likes` array
> k @family/pets/*/likes/1
< k     1       {"firstName":"John","lastName":"Doe",...}

# Name of the first pet
> k @family/pets/0/name
< k     2       {"firstName":"Jack","lastName":"Parker",...}
< k     1       {"firstName":"John","lastName":"Doe",...}
```

A node is treated as a field name. If a field name contains spaces or characters that
are special in JQL, use a double-quoted string:

```sh
> k @family/"a.b"
```

Keys that look like numbers are matched literally (`/10` addresses a key named `10`,
not array position 10).

### Matching JSON entry values

Expressions are written in square brackets: `[ <left> <operator> <right> ]`.
An expression is applied to the children of the level reached by the path in front of
it. So `/[age > 20]` checks the root-level `age` field, while `/pets/*/[kind = dog]`
checks the fields of every object of the `pets` array.

```sh
/pets/*/[name = "Rexy rex"]

/pets/*/[name eq "Rexy rex"]

/pets/*/[name = "Rexy rex" or name = Grenny]
```

NOTE: strings with spaces must be quoted.

Get documents where the owner `age` is greater than `20` and that have a pet
who likes `bones` or `toys`:

```sh
/[age > 20] and /pets/*/likes/[** in ["bones", "toys"]]
```

Here `**` as the left operand denotes any value of the current level — an element of
the `likes` array.

`ni` tests array membership with the operands reversed: `array ni value` is true when
the document field is an array containing `value`.

```sh
# Documents where `bones` is somewhere in one of the `likes` arrays
/pets/*/[likes ni "bones"]
```

Conditions can be grouped with parentheses:

```sh
(/[age <= 20] or /[lastName re "Do.*"]) and /pets/*/likes/[** in ["bones", "toys"]]
```

`~` is a prefix matching operator (since ejdb `v2.0.53`).
Prefix matching can benefit from an index.

```sh
# Documents where `/lastName` starts with "Do"
/[lastName ~ Do]
```

### Operators

Operator | Aliases | Description
--- | --- | ---
`=` | `eq` | Equal
`!=` | `!eq` | Not equal
`>` | `gt` | Greater than
`>=` | `gte` | Greater than or equal
`<` | `lt` | Less than
`<=` | `lte` | Less than or equal
`~` | | String prefix match
`!~` | | String prefix mismatch
`re` | | Regular expression match
`not re` | | Regular expression mismatch
`in` | | The document value is equal to an element of the given JSON array
`not in` | | The document value is not equal to any element of the given JSON array
`ni` | | The document array value contains the given value
`not ni` | | The document array value does not contain the given value

`!` negation is accepted only for `=`, `eq`, and `~`.
`in`, `ni`, and `re` are negated with the `not` keyword.

Examples:

```sh
/[firstName = John]
/[firstName eq John]
/[firstName != John]
/[firstName !~ Jo]
/[lastName re "Do.*"]
/[lastName not re "Do.*"]
/[age in [28, 35]]
/[age not in [28, 35]]
/[tags ni bestseller]
/[tags not ni bestseller]
```

### Arrays and maps can be matched as is

Filter documents with a `likes` array exactly matching `["bones","jumping","toys"]`:

```sh
/**/[likes = ["bones","jumping","toys"]]
```

Matching algorithms for arrays and maps are different:

* Array elements are matched from start to end. In equal arrays all values at the same
  index must be equal.
* Object maps matching consists of the following steps:
  * Lexicographically sort object keys in both maps.
  * Match the keys and their values starting from the lowest key.
  * If all corresponding keys and values in one map fully match the ones in the other map
    and vice versa, the maps are considered equal.
    For example `{"f":"d","e":"j"}` and `{"e":"j","f":"d"}` are equal maps.

A document array value is not equal to a scalar, so `/[tags = bestseller]` never matches
an array `tags`. Use `/[tags ni bestseller]` or `/tags/[** = bestseller]` instead.
A document object value is not equal to a scalar either.

### Conditions on key names

Find JSON documents having a `firstName` key at the root level. In this context `*`
denotes a key name:

```sh
/[* = "firstName"]
```

`**` on the left side compares values instead of key names. To reach keys at any depth,
put a `**` path node in front of the expression:

```sh
# Documents that have a key named `firstName` anywhere
/**/[* = "firstName"]
```

You can test a key name and a key value at the same time:

```sh
# Document has the `firstName` key with the `John` value
/[[* = "firstName"] = John]
```

The key name can be either `firstName` or `lastName`, but the value must be `John`:

```sh
/[[* in ["firstName", "lastName"]] = John]
```

This is especially useful with dynamic placeholders (C API):

```sh
/[[* = :keyName] = :keyValue]
```

### Combining filters

Filters are combined with `and` / `or` / `not`:

```sh
/[firstName = John] and /[age = 28]
/[firstName = John] and not /[age = 28]
```

NOTE: a filter (including a negated one) matches only existing JSON fields.
`/[age != 28]` will not match a document without `age`. To select documents that
lack a field, combine an existing condition with a negated one:

```sh
/[firstName = John] and not /[age = 28]
```

The conditions of a filter are evaluated left to right. A satisfied `or` operand
completes the filter immediately, so the remaining conditions of that filter are not
evaluated. Parenthesize expressions when combining `or` with `and`:

```sh
# (a or b) and c
(/[age < 30] or /[age > 40]) and @family/[lastName = Doe]
```

Parentheses must be written without spaces next to the filters:
`(/[a] or /[b]) and ...`.

Filters inside a single expression are also joined:

```sh
/[firstName = John and age = 39]
```

Such an expression matches when all conditions hold for the same object, even if they
refer to different fields.

### Matching JSON entry values with placeholders

Placeholders `:name` (or `:?` for the next free index) can be used instead of any
JSON value in an expression, ordering clause, or `skip`/`limit` option.
Placeholders are bound by the client API only; they cannot be bound over HTTP/WebSocket.

```ts
const q = db.createQuery('@users/[name = :name] and /[age > :age]');
q.setString('name', 'John');
q.setNumber('age', 20);
```

### Primary key queries

A primary key query is a special query form that cannot be combined with other filters:

```
FILTER_PK = [ '@' collection_name ] '/' '=' ( PLACEHOLDER | NUMBER | NUMBER_ARRAY );
```

In order to get documents by primary key the following options are available:

1. Use the API call `ejdb_get()`:
   ```ts
   const doc = await db.get('users', 112);
   ```
2. Use the special query construction `/=:?`, `/=112`, or `@collection/=112`:
   ```
   > k @users/=112
   ```

   Update the `tags` array of a document in the `jobs` collection (TypeScript):
   ```ts
   await db.createQuery('@jobs/=:? | apply :? | count')
     .setNumber(0, id)
     .setJSON(1, { tags })
     .completionPromise();
   ```

   An array of primary keys also matches:
   ```
   > k @users/=[112,113,114]
   ```
   ```ts
   await db.createQuery('@jobs/=[1,2,3] | apply :? | count')
     .setJSON(0, { tags })
     .completionPromise();
   ```

### Type comparison rules

JQL is a dynamically typed query language. The document value is always the left operand.

* Integers and floating point numbers are compared numerically.
* A string is compared lexicographically with another string.
* Booleans are compared as `0`/`1` against numbers, so `true = 1` and `false = 0`.
* `null` equals `null` and an empty string.
* If the document value is a number and the query value is a quoted string, the string
  is converted to a number: `/[age = "28"]` matches `"age": 28`.
* If the document value is a string and the query value is a number, the number's text
  representation is compared with the string.

Values of incompatible types (an object or array against a scalar) do not match.
A negated comparison (`!=`, `!~`, `not re`) matches in that case.

NOTE: mixing types is a common source of surprises. Always compare numbers with numbers.

## JQL data modification

The modification section is responsible for changing the content of matched documents.

```
APPLY = 'apply' ( PLACEHOLDER | JSON_OBJECT | JSON_ARRAY );
```

If a JSON object follows `apply`, it is treated as an
[RFC 7386](https://tools.ietf.org/html/rfc7386) merge patch. If a JSON array follows,
it is treated as an [RFC 6902](https://tools.ietf.org/html/rfc6902) JSON patch.
Placeholders are also supported.

For the modification examples we use a separate `jobs` collection, so the `family`
documents from the previous sections are not changed:

```sh
> k add jobs {"title":"Coding","tags":["dev"],"counter":1}
< k     1
> k add jobs {"title":"Cleaning","tags":[]}
< k     2
```

Add a `priority` field to all matched documents (RFC 7386 merge patch):

```sh
> k @jobs/[title = Coding] | apply {"priority": 10}
< k     1       {"title":"Coding","tags":["dev"],"counter":1,"priority":10}
```

Append a value to the `tags` array (RFC 6902 patch, `-` means the end of an array):

```sh
> k @jobs/[title = Coding] | apply [{"op":"add", "path":"/tags/-", "value":"home"}]
< k     1       {"title":"Coding","tags":["dev","home"],"counter":1,"priority":10}
```

### Non standard JSON patch extensions

#### increment

Increments the numeric value identified by the JSON path by the specified value.

```
Document:  {"foo": 1}
Patch:     [{"op": "increment", "path": "/foo", "value": 2}]
Result:    {"foo": 3}
```

```sh
> k @jobs/[title = Coding] | apply [{"op":"increment", "path":"/counter", "value":41}]
< k     1       {"title":"Coding","tags":["dev","home"],"counter":42,"priority":10}
```

#### add_create

Same as the JSON patch `add`, but creates intermediate object nodes for missing JSON
path segments.

```
Document: {"foo": {"bar": 1}}
Patch:    [{"op": "add_create", "path": "/foo/zaz/gaz", "value": 22}]
Result:   {"foo":{"bar":1,"zaz":{"gaz":22}}}
```

```
Document: {"foo": {"bar": 1}}
Patch:    [{"op": "add_create", "path": "/foo/bar/gaz", "value": 22}]
Result:   Error, since the element pointed to by /foo/bar is not an object
```

```sh
> k @jobs/[title = Coding] | apply [{"op":"add_create", "path":"/meta/info/level", "value":3}]
< k     1       {"title":"Coding",...,"meta":{"info":{"level":3}}}
```

#### swap

Swaps two values of a JSON document starting from the `from` path.

Swapping rules:

1. If the value pointed to by `from` does not exist, an error is raised.
1. If the value pointed to by `path` does not exist, it is set to the value from `from`,
   and then the value pointed to by `from` is removed.
1. If both values exist, they are swapped.

```
Document: {"foo": ["bar"], "baz": {"gaz": 11}}
Patch:    [{"op": "swap", "from": "/foo/0", "path": "/baz/gaz"}]
Result:   {"foo": [11], "baz": {"gaz": "bar"}}
```

```
Document: {"foo": ["bar"], "baz": {"gaz": 11}}
Patch:    [{"op": "swap", "from": "/foo/0", "path": "/baz/zaz"}]
Result:   {"foo":[],"baz":{"gaz":11,"zaz":"bar"}}
```

```sh
> k @jobs/[title = Coding] | apply [{"op":"swap", "from":"/tags/0", "path":"/priority"}]
< k     1       {"title":"Coding","tags":[10,"home"],"counter":42,"priority":"dev",...}
```

### upsert

`upsert` updates an existing document using the given JSON argument as a merge patch,
or inserts the argument as a new document when nothing is matched:

```sh
> k @jobs/[title = Gardening] | upsert {"title":"Gardening","tags":["outdoor"]}
< k     3       {"title":"Gardening","tags":["outdoor"]}
```

The returned document has the identifier of the inserted or updated document.

### Removing documents

Use the `del` keyword to remove matched elements from the collection:

```sh
> k @jobs/[title = Cleaning] | del
< k     2       {"title":"Cleaning","tags":[]}

> k @jobs/* | /title
< k     3       {"title":"Gardening"}
< k     1       {"title":"Coding"}
```

The modified documents are returned as the query result. Add `count` to the options
section to avoid transferring and converting them:

```sh
> k @jobs/* | apply {"seen": true} | count
< k     2
```

## JQL projections

Projections allow you to get only a subset of a JSON document, excluding unneeded data.

**Query placeholders are supported in projections.** Add `count` to the options if
you only need the number of matched documents.

Projection forms:

```sh
# Whole document
/* | all

# Field set: selected root fields
/* | /{firstName,lastName}

# Nested path
/* | /meta/x/y

# Array element or wildcard
/* | /pets/0
/* | /pets/*/name

# Combine and exclude
/* | /{firstName,lastName} + /pets
/* | all - /pets
```

Let's query only the pet owners' `firstName` and `lastName`:

```sh
> k @family/* | /{firstName,lastName}

< k     3       {"firstName":"John","lastName":"Ryan"}
< k     2       {"firstName":"Jack","lastName":"Parker"}
< k     1       {"firstName":"John","lastName":"Doe"}
```

Add the `pets` array to every document:

```sh
> k @family/* | /{firstName,lastName} + /pets

< k     3       {"firstName":"John","lastName":"Ryan"}
< k     2       {"firstName":"Jack","lastName":"Parker","pets":[...]}
< k     1       {"firstName":"John","lastName":"Doe","pets":[...]}
```

Exclude only the `pets` field from documents:

```sh
> k @family/* | all - /pets

< k     3       {"firstName":"John","lastName":"Ryan","age":39,...}
< k     2       {"firstName":"Jack","lastName":"Parker","age":35}
< k     1       {"firstName":"John","lastName":"Doe","age":28}
```

Fields are returned in the order they appear in the document, not in the order they
are listed in the projection. A document that has none of the requested paths
produces an empty object:

```sh
> k @family/* | /meta

< k     3       {"meta":{"x":{"y":7}}}
< k     2       {}
< k     1       {}
```

## JQL collection joins

A join materializes a reference to a document into the real document object,
replacing the reference in place. Documents are joined by their primary keys only.
Reference keys are stored in the referring document as a number or a string field.

Joins can be specified as part of a projection expression in the following form:

```
/.../field<collection
```

Where:

* `field` — JSON field containing the primary key of the joined document.
* `<` — the special mark symbol that instructs the EJDB engine to replace the `field`
  key with the body of the joined document.
* `collection` — name of the DB collection where the joined documents are located.

Here is a simple demonstration of collection joins in the interactive websocket shell:

```sh
> k add artists {"name":"Leonardo Da Vinci", "years":[1452,1519]}
< k     1
> k add paintings {"name":"Mona Lisa", "year":1490, "artist": 1}
< k     1
> k add paintings {"name":"Last Supper", "year":1498, "artist": 1}
< k     2

# List paintings documents
> k @paintings/*

# Do a simple join with the artists collection
> k @paintings/* | /artist<artists
< k     2       {"name":"Last Supper","year":1498,"artist":{"name":"Leonardo Da Vinci","years":[1452,1519]}}
< k     1       {"name":"Mona Lisa","year":1490,"artist":{"name":"Leonardo Da Vinci","years":[1452,1519]}}

# Strip all document fields except `name` and the `artist` join
> k @paintings/* | /artist<artists + /name + /artist/*
< k     2       {"name":"Last Supper","artist":{"name":"Leonardo Da Vinci","years":[1452,1519]}}
< k     1       {"name":"Mona Lisa","artist":{"name":"Leonardo Da Vinci","years":[1452,1519]}}

# Same result as above:
> k @paintings/* | /{name, artist<artists} + /artist/*
```

An unresolved reference behaves differently depending on the projection form:

* A plain join projection (`/artist<artists`) leaves the unresolved reference untouched.
* A join inside a field set (`/{name, artist<artists}`) drops the field.

```sh
> k add paintings {"name":"Lost Work", "year":1500, "artist": 999}
< k     3
> k @paintings/* | /artist<artists
< k     3       {"name":"Lost Work","year":1500,"artist":999}
< k     2       {"name":"Last Supper","year":1498,"artist":{"name":"Leonardo Da Vinci","years":[1452,1519]}}
< k     1       {"name":"Mona Lisa","year":1490,"artist":{"name":"Leonardo Da Vinci","years":[1452,1519]}}

> k @paintings/* | /{name, artist<artists}
< k     3       {"name":"Lost Work"}
< k     2       {"name":"Last Supper","artist":{"name":"Leonardo Da Vinci","years":[1452,1519]}}
< k     1       {"name":"Mona Lisa","artist":{"name":"Leonardo Da Vinci","years":[1452,1519]}}
```

A string primary key reference is also accepted:

```sh
> k add paintings {"name":"String Ref", "year":1501, "artist": "1"}
< k     4
> k @paintings/[name = "String Ref"] | /artist<artists
< k     4       {"name":"String Ref","year":1501,"artist":{"name":"Leonardo Da Vinci","years":[1452,1519]}}
```

## JQL results ordering

```
OPT = ( 'asc' | 'desc' ) ( ORDERNODES | PLACEHOLDER )
```

Add one more document and sort documents by `firstName` ascending and `age`
descending:

```sh
> k add family {"firstName":"John", "lastName":"Ryan2", "age":39}
< k     4

> k @family/* | /{firstName,lastName,age} | asc /firstName desc /age
< k     2       {"firstName":"Jack","lastName":"Parker","age":35}
< k     4       {"firstName":"John","lastName":"Ryan2","age":39}
< k     3       {"firstName":"John","lastName":"Ryan","age":39}
< k     1       {"firstName":"John","lastName":"Doe","age":28}
```

Sorting clauses are applied in the order they are written. Documents with equal
values of all ordering paths keep an implementation-defined order.

`asc`/`desc` may use an index defined for a collection to avoid a separate document
sorting stage. At most 64 ordering clauses are allowed.

## JQL options

All options are specified in a single `|` section:

```sh
> k @family/* | skip 1 limit 2
```

* `skip n` — skip the first `n` records of the result set.
* `limit n` — set the maximum number of documents in the result set. `limit 0` means
  no limit.
* `count` — return only the number of matched documents:
  ```sh
  > k @family/* | count
  < k     4
  ```
  `count` is applied after `skip`/`limit`:
  ```sh
  > k @family/* | skip 1 count
  < k     3
  ```
  Duplicate `skip` or `limit` clauses are rejected with an error.
* `noidx` — do not use any index for query execution.
* `inverse` — by default a query scans documents from the most recently added to the
  older ones. This option inverts the scan direction and implicitly enables `noidx`.
  It has no effect if the query has `asc`/`desc` ordering clauses.

```sh
> k @family/* | /{firstName,lastName} | inverse
< k     1       {"firstName":"John","lastName":"Doe"}
< k     2       {"firstName":"Jack","lastName":"Parker"}
< k     3       {"firstName":"John","lastName":"Ryan"}
< k     4       {"firstName":"John","lastName":"Ryan2"}
```

Options may be listed in any order inside the section. Placeholders can be used
for `skip` and `limit` values.

## JQL indexes and performance tips

A database index can be built for any JSON field path containing values of number or
string type. An index can be `unique` — disallowing value duplication — or `non unique`.
The following index mode bit mask flags are used (defined in `ejdb2.h`):

Index mode | Description
--- | ---
<code>0x01 EJDB_IDX_UNIQUE</code> | Index is unique
<code>0x04 EJDB_IDX_STR</code> | Index for JSON `string` field values
<code>0x08 EJDB_IDX_I64</code> | Index for `8 byte` signed integer field values
<code>0x10 EJDB_IDX_F64</code> | Index for `8 byte` floating point field values

For example, a unique index of string type is specified by
`EJDB_IDX_UNIQUE | EJDB_IDX_STR` = `0x05`.
An index can be defined for only one value type located under a specific path in a
JSON document.

Let's define a non-unique string index for the `/lastName` path:

```sh
> k idx family 4 /lastName
< k
```

Index selection for queries is based on a set of heuristic rules.

You can always check index usage by issuing the `explain` command in the WS API:

```sh
> k explain family /[lastName=Doe]
< k     explain [INDEX] MATCHED  STR|3 /lastName EXPR1: 'lastName = Doe' INIT: IWKV_CURSOR_EQ
[INDEX] SELECTED STR|3 /lastName EXPR1: 'lastName = Doe' INIT: IWKV_CURSOR_EQ
 [COLLECTOR] PLAIN
```

The following statements are taken into account when using EJDB2 indexes:

* Only one index can be used for a particular query execution. `explain` reports all
  matched indexes and the one that was selected.
* If a query contains an `or`-joined part at the top level of the query expression, or
  a negated expression at the top level, indexes are not used at all:

  ```
  # No index
  /[lastName != Doe]
  /[lastName = "John"] or /[lastName = Ryan]

  # Index is used
  /[lastName = Doe]
  /[lastName = Doe] and /[age = 28]
  /[lastName = Doe] and not /[age = 28]
  /[lastName = Doe] and /[age != 28]
  ```

* A filter path containing `*` or `**` nodes is not indexable. Use a concrete path:

  ```
  # No index
  /**/[lastName = Doe]

  # Index is used
  /[lastName = Doe]
  ```

* The following operators are supported by indexes (ejdb 2.0.x and later):
  * `eq`, `=`
  * `gt`, `>`
  * `gte`, `>=`
  * `lt`, `<`
  * `lte`, `<=`
  * `in` (unless the value list is large relative to the collection)
  * `~` (prefix matching, string indexes only)
* `ORDERBY` clauses may use an index to avoid result set sorting. Only the first
  ordering clause is eligible, and the index must match its path:

  ```
  > k explain family /* | asc /lastName
  [INDEX] SELECTED STR|3 /lastName INIT: IWKV_CURSOR_AFTER_LAST STEP: IWKV_CURSOR_PREV ORDERBY
   [COLLECTOR] PLAIN

  > k explain family /* | asc /firstName
  [INDEX] NO [COLLECTOR] SORTER
  ```
* Array fields can also be indexed. A typical use case is indexing entity tags:

  ```
  > k add books {"name":"Mastering Ultra", "tags":["ultra", "language", "bestseller"]}
  > k add books {"name":"Learn something in 24 hours", "tags":["bestseller"]}

  > k idx books 4 /tags
  > k explain books /tags/[** in ["bestseller"]]
  [INDEX] MATCHED  STR|4 /tags EXPR1: '** in ["bestseller"]' INIT: IWKV_CURSOR_EQ
  [INDEX] SELECTED STR|4 /tags EXPR1: '** in ["bestseller"]' INIT: IWKV_CURSOR_EQ
   [COLLECTOR] PLAIN
  ```

### Performance tip: physical ordering of documents

All documents in a collection are sorted by their primary key in `descending` order.
So if you use auto-generated keys (`ejdb_put_new`), documents returned by a full scan
query are ordered by insertion time in descending order, unless query sorting, indexes,
or the `inverse` keyword is used.

### Performance tip: brute force scan vs indexed access

In many cases using an index may decrease overall query performance, because the index
collection contains only document references (`id`) and the engine has to fetch each
document by its primary key to finish query matching. For not so large collections a
brute force scan may perform better than an indexed scan. However, exact matching
operations `eq` and `in`, sorting by natural index order, and prefix matching usually
benefit from an index.

### Performance tip: get rid of unnecessary document data

If you would like to update a set of documents with `apply` or `del` operations but do
not want to fetch all of them as the query result, add the `count` option: it avoids
unnecessary data transferring and JSON conversion.

## Non-trivial query cookbook

The queries below demonstrate less obvious corners of JQL. They all run against the
`family` collection from the introduction plus one intentionally quirky document:

```sh
> k add family {"firstName":"Quirky","age":42,"emptyArr":[],"emptyObj":{},"matrix":[[1,2],[3,4]],"deep":{"deeper":{"needle":"found"}},"10":"ten","a.b":"dot","tmp_counter":1}
< k     5
```

**1. Find documents by a key name at any depth.** Indexes are not used here, but the
query is convenient for unknown document schemas:

```sh
> k @family/**/[* re "^tmp_"]
< k     5       {"firstName":"Quirky",...,"tmp_counter":1}
```

**2. Find documents by a value several levels deep.** `**` can match zero or more
path levels:

```sh
> k @family/**/needle
< k     5       {"firstName":"Quirky",...,"deep":{"deeper":{"needle":"found"}},...}
```

**3. Find documents containing an empty array or an empty object.** `[** = []]`
compares every value of the current level with an empty array:

```sh
> k @family/[** = []]
< k     5       {"firstName":"Quirky",...,"emptyArr":[],...}

> k @family/[** = {}]
< k     5       {"firstName":"Quirky",...,"emptyObj":{},...}
```

**4. Match nested arrays by position.** `matrix/1/0` is the first element of the second
row:

```sh
> k @family/matrix/1/0
< k     5       {"firstName":"Quirky",...,"matrix":[[1,2],[3,4]],...}
```

**5. Find a document where some array contains a value.** `ni` works on any array value
reached by `**`:

```sh
> k @family/**/[** ni 1]
< k     5       {"firstName":"Quirky",...,"matrix":[[1,2],[3,4]],...}
```

**6. Match keys that look like numbers or contain dots.** Such keys are ordinary keys:

```sh
> k @family/10
< k     5       {"firstName":"Quirky",...,"10":"ten",...}

> k @family/"a.b"
< k     5       {"firstName":"Quirky",...,"a.b":"dot",...}
```

**7. The first pet is a dog.** Combine an array position with an expression:

```sh
> k @family/pets/0/[kind = dog]
< k     1       {"firstName":"John","lastName":"Doe",...}
```

**8. Prefix matching works on non-string values** by comparing their text
representation. `/[age ~ 2]` matches `28`, but not `35` or `39`:

```sh
> k @family/[age ~ 2]
< k     1       {"firstName":"John","lastName":"Doe","age":28,...}
```

**9. Regex on numbers.** Numeric values are converted to strings before the match,
so `^[23]` matches every age whose text representation starts with `2` or `3`:

```sh
> k @family/[age re "^[23]"]
< k     4       {"firstName":"John","lastName":"Ryan2","age":39}
< k     3       {"firstName":"John","lastName":"Ryan","age":39,...}
< k     2       {"firstName":"Jack","lastName":"Parker","age":35,...}
< k     1       {"firstName":"John","lastName":"Doe","age":28,...}
```

Use `^[23][0-9]*$` to require a full match.

**10. Value membership vs array membership.** Note the difference:

```sh
# Documents whose `tags` array contains `bestseller`
> k @family/[tags ni bestseller]
< k     3       {"firstName":"John","lastName":"Ryan","tags":["a","bestseller"],...}

# Documents having a root-level value equal to `bestseller` (array elements are not visited)
> k @family/[** = bestseller]
```
The second query returns nothing: `**` compares values only at the level reached by the
path, and `tags` is a single array value. To descend into the array use `/**/[** = ...]`
with a `**` path node.

**11. Test two fields of the same object in one expression:**

```sh
> k @family/[firstName = John and age = 39]
< k     4       {"firstName":"John","lastName":"Ryan2","age":39}
< k     3       {"firstName":"John","lastName":"Ryan","age":39,...}
```

**12. Key name and value together.** Find documents where either `firstName` or
`lastName` equals `John`:

```sh
> k @family/[[* in ["firstName","lastName"]] = John]
< k     4       {"firstName":"John","lastName":"Ryan2",...}
< k     3       {"firstName":"John","lastName":"Ryan",...}
< k     1       {"firstName":"John","lastName":"Doe",...}
```

**13. Document lacks a field.** Negate a filter; a nonexistent field never matches,
so its negation matches:

```sh
> k @family/[age = 42] and not /[lastName = Doe]
< k     5       {"firstName":"Quirky","age":42,...}
```

**14. Grouped `or` plus a collection anchor.** A leading group has no anchor, so put
`@collection` on one of the filters inside or after the group:

```sh
> k (/[age < 30] or /[age > 40]) and @family/pets/*/likes/[** = toys] and /[firstName = John]
< k     1       {"firstName":"John","lastName":"Doe","age":28,...}
```

**15. Bulk update with a count.** Update documents and return only their count:

```sh
> k @family/[age > 30] | apply {"adult": true} | count
< k     4
```

## Common pitfalls

* **Parentheses are whitespace sensitive.** `( /[a] or /[b] )` is a parse error.
  Write `(/[a] or /[b])`.
* **`or` short-circuits the rest of the filter.** See
  [Combining filters](#combining-filters).
* **Array literals contain JSON values.** `in [John]` is invalid; use `in ["John"]`.
* **A missing field is not unequal to anything.** `/[age != 28]` needs an existing
  `age`; use `and not /[age = 28]` to select documents without the field.
* **`in` and `ni` are not interchangeable.** `/[age in [28, 35]]` tests a scalar
  against a list; `/[tags ni bestseller]` tests that an array contains a value.
* **`*` is one level, `**` is any level.** In a filter path `*` consumes one nesting
  level; `**` consumes any number of levels. In an expression, a `*` left operand
  compares key names, while `**` compares values.
* **All options go into one `|` section.** `| asc /age | limit 2` is invalid;
  write `| asc /age limit 2`.
* **Sections have a fixed order:** filters, modification, projections, options.
* **Unquoted strings are limited.** Use `"..."` for strings with spaces or with any of
  `/ " [ ] = > < ! ( )`.
* **Placeholders cannot be used over HTTP/WebSocket.** They must be bound with the
  client API.
* **Projection of a missing path yields `{}`** rather than an empty result document.
* **`or` at the top level disables indexes.** Split such queries or accept the scan.
* **`inverse` or a filter with `*`/`**` disables indexes** (`inverse` implies `noidx`).
* **Numeric types are coerced.** `true = 1` and `null = ""` are true; compare values of
  the same type.

# HTTP REST/WebSocket API

EJDB2 can expose its data over the network:

* **REST API** over HTTP.
* **WebSocket API** for interactive/persistent sessions.
* **TLS** (HTTP and WebSocket) with a PEM key and certificate.

The endpoint can be started either by the standalone `jbs` server or embedded into
an application through `struct ejdb_http` / `jbr.h` (see
[Embedded HTTP server](#embedded-http-server)).

All document payloads are JSON; queries are written in
[JQL](https://github.com/Softmotions/ejdb/blob/master/src/jql/README.md).

## `jbs` server

```
Usage: jbs [options]

  -f, --file=<>        Database file path. Default: ejdb2.db
  -p, --port=NUM       HTTP server port number. Default: 9191
  -l, --listen=<>      Network address to listen on. Default: localhost
  -k, --key=<>         PEM private key file for TLS 1.2
  -c, --certs=<>       PEM certificates file for TLS 1.2
  -a, --access=TOKEN   Access token expected in the X-Access-Token header
  -r, --access-read    Allow anonymous read-only access
  -C, --cors           Enable CORS response headers
  -t, --trunc          Cleanup/reset the database file on open
  -w, --wal            Enable the write-ahead log (WAL)

Advanced options:
  -S, --sbz=NUM        Max sorting buffer size, default: 16777216, min: 1048576
  -D, --dsz=NUM        Initial buffer size for documents processed during queries,
                       default: 65536, min: 16384
  -T, --trylock        Exit with an error if the database is locked by another
                       process instead of waiting for the lock
```

Notes:

* `-b, --bind` is accepted as an alias of `-l, --listen` for backward compatibility.
* `jbs` disables the write-ahead log by default; `-w` turns it on. The embedded C API
  keeps WAL enabled unless `struct ejdb_opts.no_wal` is set.
* The access token is used as is; it is not read from a file.

Examples:

```sh
# Local server protected by an access token
./jbs -a 'myaccess01'

# Listen on all interfaces, allow anonymous reads, enable CORS
./jbs -l 0.0.0.0 -a 'myaccess01' -r -C

# TLS endpoint
./jbs -a 'myaccess01' -k server.key -c server.crt
```

## Access control

When an access token is configured (`-a` or `struct ejdb_http.access_token`), every
HTTP request and every WebSocket handshake must provide it in the `X-Access-Token`
header.

Request | Result
--- | ---
Token missing, token required | `401 Unauthorized`
Token provided but does not match | `403 Forbidden`
Token valid | Request is processed

With `-r` (`--access-read`, `read_anon = true`) an **anonymous** client (no token) may
perform read requests only:

* `GET`/`HEAD /{collection}/{id}` and `POST /` (query) are allowed.
* A query that contains an `apply`/`upsert`/`del` section is rejected with `403`.
* Any mutating request (`POST /{collection}`, `PUT`, `PATCH`, `DELETE`) is rejected
  with `401`.
* Over WebSocket, `info` and all mutating commands are rejected with
  `Access denied (JBR_ERROR_WS_ACCESS_DENIED)`.
* `OPTIONS /` is not available anonymously (`401`).

A caller that provides a **valid** token is not limited by `-r`; the flag affects only
anonymous requests.

## Embedded HTTP server

The same endpoint can be started by the `ejdb2` library. Fill
`struct ejdb_opts.http` and set `enabled = true`:

```c
struct ejdb_opts opts = {
  .kv = { .path = "example.db" },
  .http = {
    .enabled = true,
    .port = 9191,
    .bind = "localhost",           // Default: "localhost"
    .access_token = "myaccess01",  // Default: zero (no token required)
    .access_token_len = 10,
    .read_anon = true,             // Allow anonymous read-only access
    .cors = true,                  // Send CORS headers
    .blocking = false,             // false: serve in a background thread
    .ssl_private_key = "server.key",
    .ssl_certs = "server.crt",
    .max_body_size = 0             // Default: 64Mb, minimum: 512K
  }
};
struct ejdb *db;
iwrc rc = ejdb_open(&opts, &db);
```

Behaviour:

* With `blocking = false` the server runs in a background thread and `ejdb_open()`
  returns immediately.
* With `blocking = true` `ejdb_open()` enters the server loop and returns only after
  the server is stopped (this is what `jbs` does).
* `ejdb_close()` stops the embedded server and waits for it to finish.
* `jbr.h` exposes the server lifecycle directly for applications that need it:
  `jbr_start()`, `jbr_shutdown_request()`, `jbr_shutdown_wait()`, `jbr_init()`.

## HTTP REST API

### Common rules

* A collection name is a non-empty string of at most `EJDB_COLLECTION_NAME_MAX_LEN`
  (255) bytes.
* A document identifier is a positive `int64` (`>= 1`).
* Request paths are `/{collection}` or `/{collection}/{id}`.
  `{id}` must be a decimal integer; `0`, a negative value, or a non-numeric value is
  rejected with `400`.
* Missing or unparsable JSON bodies, invalid queries, and malformed paths produce
  `400 Bad Request`.
* Unknown documents produce `404 Not Found`.
* Internal failures produce `500`.
* Error responses have a `text/plain` body with a human readable description
  (for example `Not Found` or `Failed to parse JSON string (JBL_ERROR_PARSE_JSON)`).

Responses to authorized requests include `Access-Control-Allow-Origin: *` when CORS
is enabled. Authentication failures (`401`/`403`) are produced before the request is
routed and do not carry CORS headers.

### POST `/{collection}`

Add a new document to `{collection}`. The collection is created if it does not exist.

* Request body: JSON document.
* `200 OK`, `text/plain` body: the new document identifier as an `int64` number.

```sh
curl -s -X POST --data-raw '{"firstName":"John","age":28}' \
     -H 'X-Access-Token: myaccess01' http://localhost:9191/family
1
```

### GET | HEAD `/{collection}/{id}`

Retrieve a document.

* `200 OK`, `application/json` body: the document, pretty printed.
* `404 Not Found` if the document (or the collection) does not exist.
* `HEAD` returns the same status and headers, including `Content-Length`, without a body.
* `400` when the identifier is missing (`GET /{collection}`).

```sh
curl -s -H 'X-Access-Token: myaccess01' http://localhost:9191/family/1
{
 "firstName": "John",
 "age": 28
}
```

### PUT `/{collection}/{id}`

Store a document under the given numeric identifier, replacing an existing document.
The collection is created if it does not exist.

* Request body: JSON document.
* `200 OK`, `text/plain` body: `OK`.
* `400` for an invalid body or identifier.

### PATCH `/{collection}/{id}`

Patch a document with an [RFC 7396](https://tools.ietf.org/html/rfc7396) merge patch
(a JSON object) or an [RFC 6902](https://tools.ietf.org/html/rfc6902) JSON patch
(a JSON array).

* `200 OK`, `text/plain` body: `OK`.
* `400` for an invalid patch.
* `404` if the document is not found.

### DELETE `/{collection}/{id}`

Remove a document.

* `200 OK`, `text/plain` body: `OK`.
* `404` if the document is not found.
* Requires a writable (token-authenticated) client when `-r` is used.

### POST `/`

Execute a [JQL](https://github.com/Softmotions/ejdb/blob/master/src/jql/README.md)
query. The request body is the query text; the collection must be encoded in the
query with an `@collection` anchor.

* Request header `X-Hints` — comma separated hints:
  * `explain` — print the query execution plan before the results, separated by a
    `--------------------` line.
* Response is streamed with
  [HTTP chunked transfer encoding](https://en.wikipedia.org/wiki/Chunked_transfer_encoding).
* `200 OK`; each matched document is sent as:

  ```
  \r\n<document id>\t<document JSON>
  ```

  There is no trailing newline after the last document. A query that matches nothing
  returns an empty body.
* A query with the `count` option returns the number of matched documents as
  `text/plain` instead of documents.
* `400` for an empty body, a query without a collection anchor
  (`No collection specified in query (JQL_ERROR_NO_COLLECTION)`), or a query parse
  error (the parse error text is returned).
* `403` for an `apply`/`upsert`/`del` query sent by an anonymous client in read-only
  mode.

```sh
curl -s -X POST --data-raw '@family/[age > 18]' \
     -H 'X-Access-Token: myaccess01' http://localhost:9191/

2	{"firstName":"Jack","age":35}
1	{"firstName":"John","age":28}
```

With the `explain` hint:

```sh
curl -s -X POST --data-raw '@family/[age > 18]' \
     -H 'X-Access-Token: myaccess01' -H 'X-Hints: explain' http://localhost:9191/
[INDEX] NO [COLLECTOR] PLAIN
--------------------
2	{"firstName":"Jack","age":35}
1	{"firstName":"John","age":28}
```

Counting without transferring documents:

```sh
curl -s -X POST --data-raw '@family/* | count' \
     -H 'X-Access-Token: myaccess01' http://localhost:9191/
2
```

### OPTIONS `/`

Fetch database metadata as a JSON document. The response also contains the `Allow`
header with the methods accepted by the endpoint, and CORS headers when CORS is enabled.

```sh
curl -s -X OPTIONS -H 'X-Access-Token: myaccess01' http://localhost:9191/
{
 "version": "2.100",
 "file": "/var/lib/ejdb2/example.db",
 "size": 32768,
 "collections": [
  {
   "name": "family",
   "dbid": 3,
   "rnum": 2,
   "indexes": []
  }
 ]
}
```

The `Allow` header lists `GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS` for a writable
endpoint, and `GET, HEAD, POST, OPTIONS` when the server runs in read-only mode
(`-r`).

`OPTIONS /{collection}` is not supported (`400`).

## WebSocket API

The WebSocket endpoint is the server root (`GET /` with `Upgrade: websocket` on the
same port). If an access token is configured it must be sent in the
`X-Access-Token` header of the handshake.

The protocol is text based: every WebSocket text message contains one command, and a
command may produce one or more response messages. Messages are tab separated.

### Command format

```
<key> <command> [arguments]
```

`<key>` is an arbitrary client-chosen token of at most 36 bytes (not containing
whitespace). It is echoed back as the first field of every response message, so a
client can match responses to requests.

```
<key> info
<key> get     <collection> <id>
<key> set     <collection> <id> <document json>
<key> add     <collection> <document json>
<key> del     <collection> <id>
<key> patch   <collection> <id> <patch json>
<key> idx     <collection> <mode> <path>
<key> rmi     <collection> <mode> <path>
<key> rmc     <collection>
<key> query   <collection> <query>
<key> explain <collection> <query>
<key> <query>
```

Send `?` (a message consisting of a single question mark) to receive this help text.

### Response format

Response | Meaning
--- | ---
`<key>\t<metadata json>` | `info` result
`<key>\t<id>` | `add`, `set`, `del`, `patch` result
`<key>\t<id>\t<document json>` | `get` result, or one query result document
`<key>\t<explain>\t<plan>` | query execution plan (`explain`)
`<key>\t<count>` | `count` query result
`<key>` | End of a query result set. Also the successful reply of `idx`, `rmi`, `rmc`
`<key> ERROR: <description>` | Error

Examples below are shown as rendered by
[wscat](https://www.npmjs.com/package/@softmotions/wscat); response fields are
separated by horizontal tabs.

### `?`

Request the list of supported commands:

```sh
wscat -H 'X-Access-Token: myaccess01' -c http://localhost:9191
> ?
< <key> info
< <key> get     <collection> <id>
...
```

### `<key> info`

Return database metadata as a pretty printed JSON document.

```sh
> k info
< k	{
 "version": "2.100",
 "file": "/tmp/ejdb2.db",
 "size": 32768,
 "collections": [ ... ]
}
```

Anonymous clients are not allowed to call `info` in read-only mode.

### `<key> add <collection> <document json>`

Add a new document and return its generated identifier. The collection is created if
it does not exist.

```sh
> k add mycollection {"foo":"bar"}
< k	1
> k add mycollection {"foo":"bar"}
< k	2
```

### `<key> set <collection> <id> <document json>`

Store a document under the given numeric identifier, replacing an existing document.

```sh
> k set mycollection 3 {"foo":"baz"}
< k	3
```

### `<key> get <collection> <id>`

Return a document. The document is pretty printed.

```sh
> k get mycollection 1
< k	1	{
 "foo": "bar"
}
```

If the document is not found:

```sh
> k get mycollection 55
< k ERROR: Key not found. (IWKV_ERROR_NOTFOUND)
```

### `<key> del <collection> <id>`

Remove a document. Returns its identifier, or an error if the document is not found.

### `<key> patch <collection> <id> <patch json>`

Apply an RFC 7396 merge patch (JSON object) or an RFC 6902 JSON patch (JSON array) to
the document. Returns the document identifier.

### `<key> query <collection> <query>`

Execute a JQL query. Each matched document is sent as a separate message, and the
result set is terminated by a message containing only the key:

```sh
> k query family /* | /firstName
< k	3	{"firstName":"John"}
< k	2	{"firstName":"Jack"}
< k	1	{"firstName":"John"}
< k
```

A query with the `count` option returns a single message with the number of matched
documents and no termination message:

```sh
> k query family /* | count
< k	3
```

### `<key> explain <collection> <query>`

Same as `query`, but sends the execution plan first:

```sh
> k explain family /* | /firstName
< k	explain	[INDEX] NO [COLLECTOR] PLAIN
< k	3	{"firstName":"John"}
< k	2	{"firstName":"Jack"}
< k	1	{"firstName":"John"}
< k
```

### `<key> <query>`

Execute the query text given in the message. The collection must be encoded in the
query with an `@collection` anchor:

```sh
> k @family/[age > 30]
< k	2	{"firstName":"Jack","age":35}
< k
```

### `<key> idx <collection> <mode> <path>`

Create an index for the given JSON path. Returns an empty message on success. The
collection is created if it does not exist.

Index mode | Description
--- | ---
<code>0x01 EJDB_IDX_UNIQUE</code> | Index is unique
<code>0x04 EJDB_IDX_STR</code> | Index for JSON `string` values
<code>0x08 EJDB_IDX_I64</code> | Index for 64 bit signed integer values
<code>0x10 EJDB_IDX_F64</code> | Index for floating point values

For example a unique string index over `/name` uses mode `0x01 | 0x04 = 5`:

```sh
> k idx mycollection 5 /name
< k
```

### `<key> rmi <collection> <mode> <path>`

Remove an index. Returns an empty message on success, including the case when the
index does not exist. A missing collection is reported as
`Resource is not exists. (IW_ERROR_NOT_EXISTS)`.

### `<key> rmc <collection>`

Remove a collection with all its documents and indexes. Removing a missing collection
is not an error.

### Errors and malformed messages

Errors are returned as:

```
<key> ERROR: <description>
```

For example:

```sh
> k get mycollection 55
< k ERROR: Key not found. (IWKV_ERROR_NOTFOUND)
```

A message that cannot be parsed far enough to read the key (for example a lone `<key>`
without a command) terminates the WebSocket session.

# C API

EJDB2 can be embedded into any `C` or `C++` application. The public API is documented
in the following installed headers:

* [ejdb2.h](https://github.com/Softmotions/ejdb/blob/master/src/ejdb2.h.in) — storage,
  documents, collections, indexes, queries and query execution.
* [jql.h](https://github.com/Softmotions/ejdb/blob/master/src/jql/jql.h) — JQL query
  objects and placeholder binding.
* [jbr.h](https://github.com/Softmotions/ejdb/blob/master/src/jbr/jbr.h) — embedded
  HTTP/WebSocket server (requires a build with `EJDB_ENABLE_HTTP`).
* `iowow/iwjson.h` — JSON documents (`JBL`/`JBL_NODE`), provided by the
  [iowow](https://github.com/Softmotions/iowow) dependency.

The library is also available through language bindings (`src/bindings`: Node.js, JNI
and Android wrappers).

## Example

```c
#include <ejdb2/ejdb2.h>

#define CHECK(rc_)          \
  if (rc_) {                 \
    iwlog_ecode_error3(rc_); \
    return 1;                \
  }

static iwrc documents_visitor(struct ejdb_exec *ctx, struct ejdb_doc* const doc, int64_t *step) {
  (void) ctx;
  (void) step;
  // Print document to stderr
  return jbl_as_json(doc->raw, jbl_fstream_json_printer, stderr, JBL_PRINT_PRETTY);
}

int main(void) {

  struct ejdb_opts opts = {
    .kv = {
      .path = "example.db",
      .oflags = IWKV_TRUNC
    }
  };
  struct ejdb *db;   // EJDB2 storage handle
  int64_t id;        // Document id placeholder
  struct jql *q = 0; // Query instance
  JBL jbl = 0;       // Json document

  iwrc rc = ejdb_init();
  CHECK(rc);

  rc = ejdb_open(&opts, &db);
  CHECK(rc);

  // First record
  rc = jbl_from_json(&jbl, "{\"name\":\"Bianca\", \"age\":4}");
  RCGO(rc, finish);
  rc = ejdb_put_new(db, "parrots", jbl, &id);
  RCGO(rc, finish);
  jbl_destroy(&jbl);

  // Second record
  rc = jbl_from_json(&jbl, "{\"name\":\"Darko\", \"age\":8}");
  RCGO(rc, finish);
  rc = ejdb_put_new(db, "parrots", jbl, &id);
  RCGO(rc, finish);
  jbl_destroy(&jbl);

  // Now execute a query
  rc =  jql_create(&q, "parrots", "/[age > :age]");
  RCGO(rc, finish);

  struct ejdb_exec ux = {
    .db = db,
    .q = q,
    .visitor = documents_visitor
  };

  // Set query placeholder value.
  // Actual query will be /[age > 3]
  rc = jql_set_i64(q, "age", 0, 3);
  RCGO(rc, finish);

  // Now execute the query
  rc = ejdb_exec(&ux);

finish:
  jql_destroy(&q);
  jbl_destroy(&jbl);
  ejdb_close(&db);
  CHECK(rc);
  return 0;
}
```

Build and run. If the installed header enables the block-based API (`IW_BLOCKS`, which
is the case for libraries built with blocks support), a blocks-capable compiler is
required:

```sh
# Blocks enabled header (default for clang builds):
clang -std=gnu11 -fblocks -o example1 example1.c $(pkg-config --cflags --libs libejdb2)

# Otherwise:
cc -std=gnu11 -o example1 example1.c $(pkg-config --cflags --libs libejdb2)

./example1
{
 "name": "Darko",
 "age": 8
}{
 "name": "Bianca",
 "age": 4
}
```

For static linking add `--static` to `pkg-config --libs`; the query pulls in the
`libiwnet`/`libiowow`/`libbinnc` (and, with blocks, `BlocksRuntime`) dependencies.
Without `pkg-config` link with `-lejdb2`.

## Lifecycle

```c
iwrc rc = ejdb_init();                 // Once per process, before any other call
rc = ejdb_open(&opts, &db);            // Open (and optionally start the HTTP server)
...
rc = ejdb_close(&db);                  // Close and release everything
```

* `ejdb_init()` must be called once before using any EJDB2 API function.
* A storage file can be opened by one process at a time.
* A database handle can be used from multiple threads; conflicting operations are
  serialized internally per collection. All application threads must stop using the
  handle (and the `iowow` API) before `ejdb_close()` is called.
* `ejdb_open()` with `opts->http.enabled` starts the HTTP/WebSocket endpoint; see the
  [network API](https://github.com/Softmotions/ejdb/blob/master/src/jbr/README.md).

### Open options

`struct ejdb_opts`:

Field | Description
--- | ---
`kv` | `struct iwkv_opts` storage options: `path` (database file), `oflags` (for example `IWKV_TRUNC` to reset the file), `file_lock_fail_fast`, etc.
`http` | HTTP/WebSocket server options (`struct ejdb_http`), disabled by default.
`no_wal` | Do not use the write-ahead log. Default: `false`.
`sort_buffer_sz` | Max sorting buffer size; overflow is spilled to a temporary file. Default: 16 MiB, min: 1 MiB.
`document_buffer_sz` | Initial buffer size for documents processed during queries. Default: 64 KiB, min: 16 KiB.

The `struct ejdb_opts` object may be stack allocated and released after `ejdb_open()`.

## Errors

All functions return `iwrc` (`0` on success, a non-zero error code otherwise) or a
`void`/value result. Errors are structured codes from several namespaces:
`IW_ERROR_*`, `IWKV_ERROR_*`, `JBL_ERROR_*`, `EJDB_ERROR_*`, `JQL_ERROR_*`, `JBR_ERROR_*`.

```c
iwrc rc = ejdb_get(db, "parrots", 1, &jbl);
if (rc) {
  iwlog_ecode_error3(rc);        // Log the error with its symbolic name
}
```

Helpers from `iowow` simplify error propagation: `RCC` (assign and jump on error),
`RCGO` (jump on error), `RCRET` (return on error), `RCB`/`RCA` (jump with
`IW_ERROR_ALLOC` when an allocation returns zero). `iwrc_strip_code()` removes the
embedded `errno` part of a code when a specific error constant has to be compared.

Frequent errors:

Constant | Meaning
--- | ---
`IWKV_ERROR_NOTFOUND` | Document or key not found
`IW_ERROR_NOT_EXISTS` | Collection does not exist
`EJDB_ERROR_UNIQUE_INDEX_CONSTRAINT_VIOLATED` | Unique index would be violated
`EJDB_ERROR_COLLECTION_NOT_FOUND` | Collection not found (`ejdb_rename_collection`)
`EJDB_ERROR_TARGET_COLLECTION_EXISTS` | Target collection already exists
`JQL_ERROR_QUERY_PARSE` | JQL query syntax error
`JQL_ERROR_NO_COLLECTION` | Query has no `@collection` anchor and no collection was given
`JQL_ERROR_UNSET_PLACEHOLDER` | A query placeholder was not bound

## Documents

Documents are represented by `JBL` (a compact binary JSON document) or `JBL_NODE`
(an in-memory tree of JSON values). Both are created from JSON text and serialized
back to JSON; helpers come from `iowow/iwjson.h`.

```c
JBL jbl = 0;
iwrc rc = jbl_from_json(&jbl, "{\"name\":\"Bianca\",\"age\":4}");
...
jbl_destroy(&jbl);      // No-op when the handle is zero
```

Function | Description
--- | ---
`jbl_from_json(&jbl, json)` | Parse a JSON text into `JBL`
`jbl_as_json(jbl, printer, op, flags)` | Serialize; printers: `jbl_xstr_json_printer`, `jbl_fstream_json_printer`, `jbl_count_json_printer`; flags: `JBL_PRINT_PRETTY`
`jbl_destroy(&jbl)` | Release a document
`jbn_*` | In-memory tree manipulation, see `iwjson.h`

### Persisting documents

Function | Description
--- | ---
`ejdb_put(db, coll, jbl, id)` | Store a document under the given identifier (replaces an existing one)
`ejdb_put_jbn(db, coll, jbn, id)` | Same for `JBL_NODE`
`ejdb_put_new(db, coll, jbl, &id)` | Store a document under a new auto-generated identifier
`ejdb_put_new_jbn(db, coll, jbn, &id)` | Same for `JBL_NODE`
`ejdb_get(db, coll, id, &jbl)` | Fetch a document; the result must be released with `jbl_destroy()`
`ejdb_del(db, coll, id)` | Remove a document
`ejdb_patch(db, coll, patchjson, id)` | Apply an RFC 7396/6902 patch to a stored document
`ejdb_patch_jbl`, `ejdb_patch_jbn` | Same with a `JBL`/`JBL_NODE` patch
`ejdb_merge_or_put(db, coll, patchjson, id)` | Atomically merge-patch an existing document or insert a new one
`ejdb_merge_or_put_jbl`, `ejdb_merge_or_put_jbn` | Same with a `JBL`/`JBL_NODE` patch

Collections are created implicitly by the first write operation.

## Collections and indexes

Function | Description
--- | ---
`ejdb_ensure_collection(db, coll)` | Create a collection if it does not exist
`ejdb_remove_collection(db, coll)` | Remove a collection; no error if it is missing
`ejdb_rename_collection(db, coll, new_coll)` | Rename a collection
`ejdb_ensure_index(db, coll, path, mode)` | Create an index if it does not exist
`ejdb_remove_index(db, coll, path, mode)` | Remove an index; `0` if the index does not exist, `IW_ERROR_NOT_EXISTS` if the collection does not exist
`ejdb_get_meta(db, &jbl)` | Database metadata as a JSON document

Index mode bits (`ejdb_idx_mode_t`):

Mode | Description
--- | ---
`EJDB_IDX_UNIQUE` (`0x01`) | Values must be unique
`EJDB_IDX_STR` (`0x04`) | Index for string values
`EJDB_IDX_I64` (`0x08`) | Index for 64 bit signed integer values
`EJDB_IDX_F64` (`0x10`) | Index for floating point values

An index path is an RFC 6901 JSON pointer to a concrete field, for example
`/address/street`; wildcards in the middle of a path are not allowed. A path can
point to an array field to index its elements.

```c
// Unique string index over nested field
rc = ejdb_ensure_index(db, "users", "/address/street", EJDB_IDX_UNIQUE | EJDB_IDX_STR);
```

## Queries

Queries are created with the JQL API (`jql.h`), optionally bound to placeholder values,
and executed with `ejdb_exec()`.

```c
struct jql *q = 0;
iwrc rc = jql_create(&q, "parrots", "/[age > :age]");
if (!rc) {
  rc = jql_set_i64(q, "age", 0, 3);      // Bind the `:age` placeholder
}
...
jql_destroy(&q);
```

Function | Description
--- | ---
`jql_create(&q, coll, query)` | Parse a query; `coll` may be zero if the query has an `@collection` anchor
`jql_create2(&q, coll, query, mode)` | Same with `JQL_KEEP_QUERY_ON_PARSE_ERROR`/`JQL_SILENT_ON_PARSE_ERROR`
`jql_error(q)` | Parse error text (with a `<---` marker) for a kept query
`jql_set_i64/f64/str/bool/null/json/regexp(...)` | Bind a placeholder value
`jql_set_*2(...)` | Variants with an ownership callback for the bound value
`jql_reset(q, reset_cache, reset_placeholders)` | Reuse a query object for the next invocation
`jql_destroy(&q)` | Release the query object

Placeholders are written `:name` or `:?`. `:?` placeholders are bound by index
(`jql_set_*(q, 0, index, value)`), named placeholders by name.

### Executing a query

`ejdb_exec()` streams matched documents to a visitor:

```c
typedef iwrc (*ejdb_exec_visitor)(struct ejdb_exec *ctx, struct ejdb_doc *doc, int64_t *step);

struct ejdb_exec ux = {
  .db = db,           // Database handle
  .q = q,             // Query object
  .visitor = visitor, // Called for each matched document
  .opaque = my_ctx,   // Optional visitor context
  .skip = 0,          // Overrides `skip` encoded in the query
  .limit = 0,         // Overrides `limit` encoded in the query; 0 means no limit
  .log = 0,           // Optional `IWXSTR` that receives the execution plan/index usage
  .cnt = 0            // Out: number of documents passed to the visitor
};
iwrc rc = ejdb_exec(&ux);
```

Visitor contract:

* `doc->raw` is the stored document; `doc->node` is set only when the query has an
  `apply` or projection section.
* `doc` and its data are valid only during the callback; copy what must outlive it.
* Set `*step` to `1` (default) to advance to the next document, `0` to stop iteration,
  or another value to move the cursor by that number of documents (used for advanced
  iteration over sorted results).
* `ejdb_exec()` applies modifications (`apply`/`upsert`/`del`) to the storage.

Collecting results into a list instead of streaming:

Function | Description
--- | ---
`ejdb_list(db, q, &first, limit, pool)` | Fill a linked list of documents using a caller-provided `iwpool` (not zero); the caller owns and destroys the pool
`ejdb_list2(db, coll, query, limit, &list)` | Same from a query text
`ejdb_list3(db, coll, query, limit, log, &list)` | Same with an execution plan buffer
`ejdb_list4(db, q, limit, log, &list)` | Same from a query object
`ejdb_list_destroy(&list)` | Release a result list

```c
struct ejdb_list *list = 0;
iwrc rc = ejdb_list3(db, "parrots", "/[age > 3]", 0 /* limit */, 0 /* optional IWXSTR log */, &list);
if (!rc) {
  for (struct ejdb_doc *doc = list->first; doc; doc = doc->next) {
    jbl_as_json(doc->raw, jbl_fstream_json_printer, stderr, JBL_PRINT_PRETTY);
  }
  ejdb_list_destroy(&list);
}
```

Collecting a whole result set can be memory consuming for large collections; prefer
`ejdb_exec()` with a visitor, or set a limit.

### Count and update helpers

Function | Description
--- | ---
`ejdb_count(db, q, &count, limit)` | Execute a query and return the number of matched documents
`ejdb_count2(db, coll, query, &count, limit)` | Same from a query text
`ejdb_update(db, q)` | Execute an update query (with an `apply` section)
`ejdb_update2(db, coll, query)` | Same from a query text

`ejdb_get_iwkv(db, &kv)` | Access the underlying IWKV storage (advanced use)

## Thread safety and lifetime summary

Object | Ownership
--- | ---
`struct ejdb *` | Owned by the caller; released by `ejdb_close()`; shareable between threads
`JBL` | Owned by the caller; released by `jbl_destroy()`; returned by `ejdb_get()`/`ejdb_get_meta()`
`struct jql *` | Owned by the caller; released by `jql_destroy()`
`struct ejdb_list *` | Owned by the caller; released by `ejdb_list_destroy()`
`struct ejdb_doc` (visitor) | Valid only during the visitor callback
`struct ejdb_exec.pool` | Optional memory pool for apply/projection nodes owned by the caller
